# 阶段质量门检查单（Stage-Gate Checklist）

> 本文是 `software-dev-full-lifecycle` Skill 的配套检查单，供 AI 在每个阶段结束做 Gate 决策时逐项勾选。对齐 SKILL.md 各阶段「Gate 检查」与六条铁律。每项标注关联文档（27 份清单，见 delivery-and-docs）。准入/准出条件明确，未达准出禁止进入下一阶段（铁律 1）。

使用方式：复制对应 Gate 区块，逐条打 `[x]`；任一必勾项未过则 Gate 不通过，记录例外需用户明确确认（铁律 1）。

---

## Gate 0：需求基线准入前（P0 → P1 出口）

**准入条件**：项目已启动，用户已提供业务域初步信息。
**准出条件**：范围、目标、选型、风险均确认，方可进入需求工程。

- [ ] 目标是否可量化（如"审批周期 3 天→1 天"）？ —— 关联 `01-项目立项建议书`
- [ ] 范围外（Out of Scope）清单是否明确？ —— 关联 `01-项目立项建议书`
- [ ] 技术选型是否有 ≥2 方案对比与加权推荐理由？ —— 关联 `02-可行性研究报告`
- [ ] 是否有 WBS 与里程碑计划？ —— 关联 `03-项目开发计划`、`04-里程碑与版本规划`
- [ ] 风险是否识别并有应对措施？ —— 关联 `02-可行性研究报告`
- [ ] 是否停下来让用户确认了范围与技术选型？（铁律 1 节奏）

---

## Gate 1：需求基线 Gate（P1 → P2 出口）

**准入条件**：P0 Gate 通过，已完成需求采集与建模。
**准出条件**：SRS 评审通过并基线化（v1.0），每条需求有验收标准，方可进入设计。

- [ ] 每条需求是否有唯一编号与验收标准（GWT/可测）？ —— 关联 `05-SRS`
- [ ] 是否用至少 4 种方法表达需求（用例图/状态图/流程图/原型等）？ —— 关联 `06-用例规格说明书`、`15-原型设计说明书`
- [ ] RTM 是否覆盖全部需求（需求数=RTM 行数）？ —— 关联 `09-需求跟踪矩阵RTM`
- [ ] 是否有待定问题清单（Q-01…）并标注状态？ —— 关联 `05-SRS` 附录、`08-访谈纪要`
- [ ] SRS 是否已基线化（v1.0，冻结）？ —— 关联 `05-SRS`、`10-变更管理与基线记录`
- [ ] 用户故事是否均有 AC 与 MoSCoW 优先级？ —— 关联 `07-用户故事与产品待办列表`
- [ ] 是否已召开需求评审并记录结论与待办？ —— 关联 `08-需求调研计划与访谈纪要`

---

## Gate 2：设计评审 Gate（P2 → P3 出口）

**准入条件**：Gate 1 通过，SRS v1.0 已基线。
**准出条件**：设计评审通过，SRS 每条需求有对应设计，方可进入编码。

- [ ] SRS 每条需求是否有对应设计（可在 RTM 查到）？ —— 关联 `11~16` 全套设计、`09-RTM`
- [ ] 是否有 ADR 且 ≥5 条（含背景/决策/理由/权衡）？ —— 关联 `11-总体架构设计`
- [ ] 状态机/决策表是否完整定义了异常分支？ —— 关联 `12-数据库设计`、`16-详细设计说明书`
- [ ] 数据字典（枚举/状态）是否集中定义？ —— 关联 `12-数据库设计`
- [ ] 原型是否经过至少一轮评审并记录结果？ —— 关联 `14-UI设计规范`、`15-原型设计说明书`
- [ ] 接口契约是否写明失败场景与错误码？ —— 关联 `13-API接口设计`
- [ ] 金额是否用整数分、审计是否禁止物理删除？ —— 关联 `12-数据库设计`、`17-编码规范`

---

## Gate 3：编码完成 Gate（P3 → P4 出口）

**准入条件**：Gate 2 通过，设计已评审。
**准出条件**：类型检查/构建零错误，功能覆盖全部 Must 需求，方可进入测试。

- [ ] 类型检查是否零错误（strict 模式）？ —— 关联 `17-编码规范`、`19-环境搭建与运行手册`
- [ ] 构建是否通过、能否一键启动（`npm i && npm run dev`）？ —— 关联 `19-环境搭建与运行手册`
- [ ] 是否覆盖全部 Must 需求（RTM 标记已实现）？ —— 关联 `20-模块实现说明`、`09-RTM`
- [ ] 业务阈值是否全部集中在 config（无硬编码魔法数字）？ —— 关联 `17-编码规范`、`20-模块实现说明`
- [ ] Git 提交是否遵循 Conventional Commits、有 tag？ —— 关联 `18-Git协作与分支管理规范`
- [ ] 破坏性操作是否二次确认、失败是否不静默？ —— 关联 `17-编码规范`
- [ ] 单文件是否 ≤300 行、组件只展示业务在 service/domain？ —— 关联 `17-编码规范`

---

## Gate 4：测试通过 Gate（P4 → P5 出口）

**准入条件**：Gate 3 通过，可运行代码就绪。
**准出条件**：用例执行率 100%、通过率 ≥95%、无 Blocker/Critical 残留，方可交付。

- [ ] 用例执行率是否 100%？ —— 关联 `22-测试用例集`、`21-测试计划`
- [ ] 通过率是否 ≥95%？ —— 关联 `24-测试报告`
- [ ] 无 Blocker / Critical 缺陷残留？ —— 关联 `23-缺陷管理记录`、`24-测试报告`
- [ ] 每条 Must 需求是否有对应用例并通过（RTM 闭环）？ —— 关联 `09-RTM`、`22-测试用例集`
- [ ] 缺陷单是否含根因分析、生命周期完整？ —— 关联 `23-缺陷管理记录`
- [ ] 非功能需求是否逐条验证并给出结论？ —— 关联 `24-测试报告`、`05-SRS`(NFR)
- [ ] 测试报告是否含执行率/通过率/缺陷分布/准出结论？ —— 关联 `24-测试报告`

---

## Gate 5：交付 Gate（P5 出口 / 结项）

**准入条件**：Gate 4 通过，测试报告 Go。
**准出条件**：用户验收通过，可一键部署启动，方可结项。

- [ ] 用户能否照手册独立完成核心业务（端到端演练）？ —— 关联 `25-用户操作手册`
- [ ] 是否可一键部署（构建+SPA fallback 配置正确）？ —— 关联 `26-部署与运维手册`
- [ ] 是否坦率列出已知限制（未隐藏）？ —— 关联 `26-部署与运维手册`（反模式 9）
- [ ] 备份/重置/回滚方案是否具备？ —— 关联 `26-部署与运维手册`
- [ ] 结项总结是否含交付对照、过程数据、经验三段？ —— 关联 `27-项目结项与总结报告`
- [ ] 文档索引(00)是否更新、27 份文档数字一致（需求数=RTM=用例关联）？ —— 关联 `00-文档索引`、`delivery-and-docs`
