# 交付与文档规范

> 本文是 `software-dev-full-lifecycle` Skill 的配套规范参考，供 AI 在 P5 交付与运维阶段及全程文档管理时遵循。内容对齐 SKILL.md「配套资源」与六阶段产出，给出 **27 份文档完整清单 + 每份写作要点 + 必要表格模板**，以及文档间追溯关系、文档头规范、部署/运维/结项写法。

文档不是"写完代码补的作业"，而是流程的工程证据。本文与 `SKILL.md` 反模式 10（一次性生成 27 份却不检查一致性）直接对抗：**文档须随阶段产出、相互数字一致、能串成追溯链**。

```
01/02/03/04 ──范围/目标──> 05 SRS ──逐条需求──> 06 用例 / 07 故事
                                       │
```

## 4. 部署与运维要点（26-部署与运维手册）

- **构建产物**：`npm run build` 产出 `dist/` 静态产物；若含前端路由须配置 **SPA fallback**（所有未知路径回退 `index.html`），否则刷新子路由 404。
- Web 服务器示例（Nginx）：
```nginx
location / { try_files $uri $uri/ /index.html; }
```
- **备份/恢复**：DB 每日全量 + 增量；提供 `reset-demo.sql` 一键重置演示数据（教学场景）。
- **容量/监控**：记录预期并发与数据量上限；监控错误率与构建产物大小。
- **回滚**：保留上一版 `dist` 与 tag，异常时切回。
- **已知限制**：必须坦率列出（反模式 9），如"不支持 IE、未做移动端适配"。

## 5. 结项与经验总结写法（27-项目结项与总结报告）

- 交付对照：计划范围 vs 实际交付，逐条标注达成/裁剪/延期。
- 过程数据：需求总数、变更数、用例数、缺陷数（各级别）、通过率。
- 经验总结三段：**做得好的**（如 RTM 全程贯穿）、**不足的**（如原型评审偏晚）、**重做会怎么改**（如更早定金额口径）。
- 遗留问题 + 后续规划（对标 04 里程碑未完项）。
