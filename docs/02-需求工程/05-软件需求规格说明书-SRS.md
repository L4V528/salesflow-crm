## 1. 引言

### 1.1 编写目的

本文档定义 SalesFlow CRM 的功能需求、非功能需求、数据需求与接口需求，作为设计、开发、测试、验收与需求变更的唯一基准。本文档面向产品经理、UI 设计师、开发工程师、测试工程师及甲方业务代表。

### 1.2 适用范围

本系统面向中小型 B2B 企业的销售部门，覆盖从市场线索获取到销售回款完成（Lead to Cash，简称 L2C）的完整业务闭环，不包含生产制造、财务总账、人力资源等 ERP 其他模块。

### 1.3 术语与缩略语

| 术语 | 英文 | 定义 |
|---|---|---|
| 线索 | Lead | 尚未确认购买意向的潜在客户信息，是销售漏斗的最前端 |
| 客户 | Customer | 已完成线索转化、建立正式合作档案的企业法人主体 |
| 联系人 | Contact | 客户方的关键决策人、使用者或对接人 |
| 商机 | Opportunity | 针对特定客户的、有金额预估和成交时间预期的销售机会 |
| 报价单 | Quotation | 面向客户出具的产品价格方案，需按折扣率触发审批 |
| 合同订单 | Order | 报价审批通过后与客户签署的正式销售合同 |
| 回款计划 | Payment Plan | 订单约定的分期收款安排（首付/验收款/尾款） |
| L2C | Lead to Cash | 从线索到回款的全流程 |
| 漏斗 | Pipeline | 商机按阶段分布的转化视图 |

## 2. 总体描述

### 2.1 业务背景与现状问题

目标企业当前的销售管理依赖 Excel 表格与微信群沟通，存在四类突出问题：

1. **线索流失**：市场线索沉淀在个人手中，无人跟进即失效，无法量化转化率；
2. **商机不可视**：管理层只能在月末靠口头汇报了解进展，无法预判季度目标达成情况；
3. **审批失控**：报价折扣凭口头请示，无留痕，事后难以追溯责任；
4. **回款脱节**：合同签署后由财务单独记账，销售不知道账期，催收滞后。

本系统以"流程在线化 + 数据可视化 + 审批留痕化"为核心目标解决上述问题。

### 2.2 产品定位

一个 PC Web 端的销售业务协同平台，强调**流程驱动**而非数据记录：每个业务对象都有明确的状态机，每个状态变更都有触发条件、责任人和留痕。

### 2.3 用户角色与权限

| 角色 | 英文标识 | 职责 | 关键权限 |
|---|---|---|---|
| 销售员 | `SALES` | 跟进线索、维护客户、推进商机、发起报价与回款登记 | 仅可操作归属自己的数据 |
| 销售经理 | `MANAGER` | 分配线索、辅导商机、一级审批报价、查看团队业绩 | 可查看本部门全部数据；审批权限 |
| 商务财务 | `FINANCE` | 审核合同、确认回款到账、管理开票 | 订单与回款模块全部权限；无客户归属限制 |
| 系统管理员 | `ADMIN` | 用户与组织架构维护、产品目录、数据字典 | 全部权限（含系统管理） |

### 2.4 系统运行环境

- 客户端：Chrome / Edge / Firefox 最新两个大版本，显示分辨率 ≥ 1440×900（PC 优先，非移动端）
- 服务端：Node.js ≥ 20，数据持久化采用浏览器本地存储 + 可选后端 API（本期实现为前端本地持久化）

### 2.5 设计约束

1. 本期为单页应用（SPA），不依赖后端服务即可完整演示业务闭环；
2. 数据持久化采用浏览器 LocalStorage，需支持一键重置为演示数据；
3. 所有金额精确到分，计算过程使用整数分存储以避免浮点误差；
4. 界面语言为简体中文，日期格式 `YYYY-MM-DD`。

### 2.6 假设与依赖

- 假设企业已确定折扣审批阈值（≥15% 需经理审批，≥30% 需经理 + 总监两级审批）；
- 假设同一客户在同一时间仅允许一个进行中的商机（避免内部撞单）；
- 依赖浏览器对 LocalStorage 的支持（容量 ≥ 5MB）。

## 3. 功能需求

### 3.1 功能总览

| 编号 | 模块 | 功能点 | 优先级 |
|---|---|---|---|
| F-01 | 用户与权限 | 登录、角色鉴权、演示账号切换 | Must |
| F-02 | 工作台 | 待办聚合、今日跟进提醒、漏斗概览卡片 | Must |
| F-03 | 线索管理 | 线索列表、录入、批量分配、跟进记录、转化/废弃 | Must |
| F-04 | 客户管理 | 客户列表、客户 360 详情、联系人维护 | Must |
| F-05 | 商机管理 | 商机看板（拖拽推进阶段）、商机详情、阶段留痕、赢单/输单 | Must |
| F-06 | 报价与审批 | 报价单创建、产品明细、折扣计算、审批流发起与处理 | Must |
| F-07 | 合同订单 | 订单生成、合同审核、订单状态推进 | Must |
| F-08 | 回款管理 | 回款计划生成、回款登记、财务确认、开票管理 | Must |
| F-09 | 数据看板 | 销售漏斗、业绩排行、目标达成、月度趋势 | Should |
| F-10 | 系统管理 | 用户管理、产品目录、数据字典 | Should |

### 3.2 F-01 用户与权限

**FR-01-01** 系统应提供登录页面，用户输入账号密码后校验。

**FR-01-02** 系统应支持四种角色，登录后按角色加载可见菜单与可操作按钮（权限控制粒度到按钮级）。

**FR-01-03** 系统应提供演示模式：在登录页展示四个角色的演示账号并可一键登录，便于评审演示。**前置条件**：无。**后置条件**：会话建立，跳转工作台。

**FR-01-04** 数据可见性规则：
- `SALES`：仅可见 `ownerId` 等于自身的线索、客户、商机、报价、订单
- `MANAGER`：可见本部门所有成员的上述数据
- `FINANCE`：仅可见订单、回款、发票相关数据，且无归属限制
- `ADMIN`：全部数据

### 3.3 F-02 工作台

**FR-02-01** 工作台应展示四个统计卡片：待跟进线索数、进行中商机数、待我审批的报价数、本月回款计划金额（按当前登录角色动态计算）。

**FR-02-02** 工作台应展示"今日待跟进"列表：取 `nextFollowAt` 为今天的跟进任务，支持一键跳转对应线索。

**FR-02-03** 工作台应展示"我的商机漏斗"缩略视图：按阶段显示商机数量与金额。

**FR-02-04** 工作台应展示最近动态时间线（最近 8 条业务操作记录）。

### 3.4 F-03 线索管理

**线索状态机**：

```
待分配(NEW) ──分配──> 跟进中(FOLLOWING) ──转化──> 已转化(CONVERTED)
     │                      │
     └──分配──┘              └──废弃──> 已废弃(LOST)
```

**FR-03-01** 系统应支持线索录入，字段包括：公司名称\*、联系人姓名\*、联系电话\*、来源渠道\*、所属行业、意向等级（高/中/低）、备注。标注 \* 为必填。

**FR-03-02** 系统应支持线索列表展示，提供按来源、状态、归属人、关键词的多条件组合筛选与排序。

**FR-03-03** 销售经理应可对状态为"待分配"的线索执行批量分配，指定归属销售员，系统记录分配人与分配时间。**业务规则**：一次最多分配 50 条。

**FR-03-04** 系统应支持对线索添加跟进记录，字段包括：跟进方式（电话/拜访/邮件/微信）、跟进内容\*、下次跟进时间、跟进结果。**业务规则**：添加跟进后线索状态自动变为"跟进中"。

**FR-03-05** 系统应支持线索转化。**业务规则**：
- 转化时校验公司名称是否已存在客户档案，若存在则提示关联至已有客户，避免重复建档；
- 转化成功后生成客户档案 + 默认联系人，线索状态置为"已转化"，并记录转化人与时间；
- 转化时可同步创建商机（可选）。

**FR-03-06** 系统应支持线索废弃，废弃必须填写废弃原因（枚举：无采购需求/预算不足/已选竞品/联系不上/信息无效/其他）。

**FR-03-07** 系统应在列表页展示线索来源分布与转化率统计。

### 3.5 F-04 客户管理

**FR-04-01** 系统应提供客户列表，字段包括：客户编号、客户名称、所属行业、客户等级（A/B/C）、归属销售、创建时间、关联商机数、累计成交金额。

**FR-04-02** 系统应提供客户 360 详情视图，以标签页形式聚合展示：
- 基础信息（可编辑）
- 联系人列表（支持增改、设置主联系人）
- 关联商机
- 历史订单
- 回款记录
- 操作日志

**FR-04-03** 系统应支持客户转移（更换归属销售），转移时可选择是否同步转移该客户下进行中的商机。**业务规则**：转移操作需记录原归属人与新归属人。

**FR-04-04** 系统应支持客户等级自动评定。**业务规则**：根据累计成交金额自动计算 —— 累计 ≥ 50 万为 A 级，≥ 10 万为 B 级，其余为 C 级；允许人工覆盖并标注原因。

### 3.6 F-05 商机管理

**商机阶段状态机**（核心业务规则）：

| 阶段 | 名称 | 赢率 | 进入条件 | 可流转至 |
|---|---|---|---|---|
| S1 | 初步接洽 | 10% | 创建商机 | S2 / 输单 |
| S2 | 需求确认 | 30% | 已填写需求确认信息 | S3 / S1 / 输单 |
| S3 | 方案报价 | 60% | 已创建至少一张报价单 | S4 / S2 / 输单 |
| S4 | 商务谈判 | 80% | 报价单审批通过 | S5(赢单) / S3 / 输单 |
| S5 | 赢单 | 100% | 合同订单已签约 | 终态 |
| — | 输单 | 0% | 任意阶段可标记 | 终态 |

**FR-05-01** 系统应提供商机看板视图（Kanban），按阶段分列展示商机卡片，卡片显示客户名、商机标题、金额、负责人、预计成交日。**业务规则**：支持拖拽卡片改变阶段，拖拽时校验阶段推进的前置条件，不满足则拒绝并给出明确提示（例如未创建报价单不许拖到"方案报价"）。

**FR-05-02** 系统应支持商机列表视图与看板视图切换。

**FR-05-03** 系统应记录每次阶段变更为一条阶段历史，包含：原阶段、新阶段、操作人、时间、备注。**业务规则**：阶段历史不可删除。

**FR-05-04** 系统应支持赢单操作。**业务规则**：赢单前必须存在已签约的订单；赢单时填写实际成交金额。

**FR-05-05** 系统应支持输单操作。**业务规则**：输单必须填写输单原因（价格过高/竞品胜出/无预算/项目取消/客户失联/其他）与竞品名称（可选）。

**FR-05-06** 系统应支持商机金额与赢率加权预测：`加权预测金额 = 商机金额 × 阶段赢率`，在看板顶部展示各阶段加权汇总。

**FR-05-07** 撞单校验：为同一客户创建商机时，若该客户已存在进行中的商机，系统应弹出警告并要求二次确认。

### 3.7 F-06 报价与审批

**FR-06-01** 系统应支持在商机下创建报价单，字段包括：报价单编号（自动生成）、关联商机\*、报价有效期\*、产品明细\*（产品、单价、数量、折扣率）、付款方式、备注。

**FR-06-02** 系统应自动计算：
- `明细小计 = 单价 × 数量`
- `报价总额 = Σ 明细小计`
- `折扣后金额 = Σ (明细小计 × (1 - 折扣率))`
- `整体折扣率 = 1 - 折扣后金额 / 报价总额`

**FR-06-03** 审批触发规则（决策表）：

| 规则 | 条件（整体折扣率 d） | 处理 | 审批链 |
|---|---|---|---|
| R1 | d < 15% | 无需审批，可直接定稿 | — |
| R2 | 15% ≤ d < 30% | 需一级审批 | 销售经理 |
| R3 | d ≥ 30% | 需两级审批 | 销售经理 → 销售总监 |
| R4 | 任意 d，且金额 ≥ 100 万 | 强制两级审批 | 销售经理 → 销售总监 |

**FR-06-04** 报价单状态机：

```
草稿(DRAFT) ──提交──> 审批中(APPROVING) ──全部通过──> 已通过(APPROVED) ──生成订单──> 已转订单(CONVERTED)
                            │                  │
                            └──任一驳回──> 已驳回(REJECTED) ──修改后重新提交──> 审批中(APPROVING)
                            │
                            └──撤回──> 草稿(DRAFT)
```

**FR-06-05** 审批人应在审批中心看到待办，可执行通过/驳回操作，驳回必须填写驳回意见。**业务规则**：驳回后报价单回到草稿状态，创建人修改后可再次提交，审批链从头开始。

**FR-06-06** 系统应在报价单详情页可视化展示审批链：显示每一级的审批人姓名、角色、状态（待审批/已通过/已驳回）、处理时间、审批意见。

**FR-06-07** 报价单已通过后应可一键生成合同订单，生成时带入客户、产品明细与折后金额。

**FR-06-08** 报价超过有效期（当前日期 > 有效期）时，系统在列表与详情以"已过期"标记提示，且不允许生成订单。

### 3.8 F-07 合同订单

**FR-07-01** 系统应支持订单生成，字段包括：订单编号（自动生成）、关联客户\*、关联报价单、合同金额\*、签订日期\*、交付日期、付款方式、合同编号（手工录入）。

**FR-07-02** 订单状态机：

```
待签约(PENDING) ──商务审核通过──> 已签约(SIGNED) ──开始交付──> 执行中(EXECUTING) ──交付完成──> 已完成(COMPLETED)
       │                │
       └──作废──> 已取消(CANCELLED)
```

**FR-07-03** 商务财务角色应可在订单详情页执行商务审核（通过/驳回），审核通过后订单状态变为"已签约"。

**FR-07-04** 订单签约时系统应自动生成回款计划。**业务规则**：默认按付款方式生成分期：
- 全额预付：1 期，100%，计划日期 = 签订日期 + 7 天
- 三三四：3 期，30%/30%/40%，分别为签订日期 +7 天 / +30 天 / +90 天
- 验收后付：2 期，50%/50%，签订日期 +7 天 / 交付日期 +15 天
- 允许人工调整每期金额与日期

**FR-07-05** 系统应在订单列表展示订单金额、已回款金额、回款进度百分比。

### 3.9 F-08 回款管理

**FR-08-01** 系统应提供回款计划列表，展示：关联订单、客户、期次、计划金额、计划日期、已回款金额、状态。

**FR-08-02** 回款计划状态规则：
- 已回款金额 = 0 且计划日期 ≥ 今天 → 未回款
- 0 < 已回款金额 < 计划金额 → 部分回款
- 已回款金额 ≥ 计划金额 → 已回款
- 已回款金额 < 计划金额 且 计划日期 < 今天 → **逾期**（界面高亮红色）

**FR-08-03** 销售员应可登记回款，字段包括：回款金额\*、回款方式（电汇/承兑/现金/POS）、回款日期\*、关联期次、流水号、备注。

**FR-08-04** 商务财务应可对已登记的回款执行到账确认。**业务规则**：确认后该笔回款计入订单已回款金额与客户累计成交金额；未确认的回款以"待确认"状态展示，不计入统计。

**FR-08-05** 系统应支持开票管理：财务可为已确认回款开具发票，登记发票号与开票日期，状态为"未开票/已开票/已寄出"。

**FR-08-06** 系统应提供回款逾期预警：首页与回款页展示逾期期次数量与逾期金额合计。

### 3.10 F-09 数据看板

**FR-09-01** 系统应展示销售漏斗图：按商机阶段展示商机数量与金额，并计算相邻阶段转化率。

**FR-09-02** 系统应展示销售业绩排行榜：按已确认回款金额对销售员排名，展示目标额、完成额、达成率进度条。

**FR-09-03** 系统应展示近 12 个月的回款金额趋势折线图。

**FR-09-04** 系统应展示线索来源分布饼图与线索转化率。

**FR-09-05** 所有图表应支持按时间范围（本季度/本年度/全部）与部门筛选。

### 3.11 F-10 系统管理

**FR-10-01** 管理员可维护用户：新增/编辑/停用，设置姓名、账号、角色、所属部门、手机号。

**FR-10-02** 管理员可维护产品目录：产品名称、规格型号、单位、标准单价、所属分类、上架状态。

**FR-10-03** 管理员可维护数据字典：客户行业、客户来源、线索来源、输单原因、废弃原因等枚举项。

**FR-10-04** 管理员可执行数据维护：一键重置为演示数据、导出全部数据为 JSON 文件。

## 7. 其他需求

### 7.1 验收标准

系统满足以下条件视为验收通过：

1. 完成 SRS 中全部 **Must** 优先级功能；
2. 测试用例通过率 ≥ 95%，无致命（Blocker）与严重（Critical）缺陷残留；
3. 可在全新环境通过 `npm install && npm run dev` 一键启动；
4. 可完整演示一条端到端业务流程（见 7.2 主成功场景）；
5. 交付全部 27 份技术文档。

### 7.2 端到端主成功场景（验收演示脚本）

1. 销售经理登录 → 线索管理 → 将 3 条待分配线索分配给销售员张伟；
2. 销售员张伟登录 → 工作台看到待办变化 → 对线索"华远科技"添加电话跟进；
3. 张伟将线索转化为客户 → 自动创建联系人 → 同步创建商机；
4. 张伟推进商机阶段至"需求确认" → 创建报价单，添加 2 个产品，折扣率设为 20%；
5. 提交审批 → 系统按规则 R2 生成一级审批 → 销售经理李娜收到待办；
6. 李娜审批通过 → 报价单状态变为已通过；
7. 张伟一键生成订单 → 填写合同编号 → 提交商务审核；
8. 财务王芳审核通过 → 订单已签约 → 系统自动生成 3 期回款计划；
9. 张伟登记首期回款 → 王芳确认到账 → 订单回款进度更新；
10. 查看数据看板：漏斗、排行、趋势图表同步更新。

### 7.3 约束与风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 需求理解偏差 | 返工 | 原型评审 + 用户故事验收标准双重确认 |
| 本地存储容量上限 | 大数据量失败 | 数据量控制在 5MB 内，提供导出/重置 |
| 演示数据与真实业务脱节 | 答辩说服力不足 | 演示数据按真实业务语义构造，含异常与逾期场景 |
