### 1.2 优先级定义

| 优先级 | 定义 | 执行要求 |
|---|---|---|
| **P0** | 核心业务规则、主流程、权限基线、数据一致性 | 必须 100% 通过，否则不予准出 |
| **P1** | 重要功能点、常用异常与反向场景 | 本轮必须通过 |
| **P2** | 展示类、统计类、易用性与兼容性 | 允许遗留 Minor 缺陷 |

### 1.3 用例类型定义

| 类型 | 说明 |
|---|---|
| 正向 | 正常业务流程与合法输入的验证 |
| 反向 | 异常输入、权限不足、状态前置条件不满足等被拒绝场景 |
| 边界 | 业务规则临界取值（折扣率、金额、条数、等级阈值、溢收） |
| 权限 | 角色可见性与可操作性的差异验证 |
| 端到端 | 跨模块完整业务流 |
| 非功能 | 性能、易用性、可靠性、安全性、可维护性、可移植性 |

所有测试数据均取自 `app/src/data/seed.ts` 预置演示数据，执行前一律执行「系统管理 → 一键重置演示数据」，确保基线一致。核心对象清单见《测试计划》SFS-CRM-TP-01 第 4.3 节。
